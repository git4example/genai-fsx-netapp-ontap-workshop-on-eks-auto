feat(iam): Replace AdministratorAccess with scoped least-privilege role

Remove the temporary AdministratorAccess that was attached to the
VSCodeInstanceRole for policy-generation testing and replace it with a
layered least-privilege configuration:

1. Baseline AWS managed policies (safety net, jumpbox-appropriate):
   - AmazonSSMManagedInstanceCore  (SSM Session Manager, SSM agent)
   - CloudWatchAgentServerPolicy   (CloudWatch agent)
   - AmazonQDeveloperAccess        (Amazon Q in VSCode)
   - ReadOnlyAccess                (broad describe/list)
   - AmazonVPCFullAccess           (Terraform VPC provisioning)
   - AmazonEC2FullAccess           (Terraform EC2 provisioning)
   - IAMFullAccess                 (eksctl + Terraform IAM roles)

   Explicitly NOT attached (wrong principal type for a jumpbox):
   - AmazonEKSClusterPolicy   (for EKS control plane service role)
   - AmazonEKSWorkerNodePolicy (for worker node IAM role)
   - AmazonEKS_CNI_Policy     (for VPC CNI IRSA role)

2. Inline WorkshopLeastPrivilege policy (14 statements) derived from
   IAM Access Analyzer policy generation (Option 1) plus identified
   gaps the generator missed. Resource-scoped where possible:
   - EKS cluster/addon/access-entry lifecycle
   - FSx ONTAP file-system/SVM/volume lifecycle
   - IAM PassRole scoped to workshop services
   - IAM CreateServiceLinkedRole scoped to workshop services
   - CloudFormation lifecycle scoped to eksctl-* and workshop stacks
   - KMS lifecycle for encryption
   - Secrets Manager scoped to trident-fsx-*, vscode-*, eks-* prefixes
   - CloudWatch Logs lifecycle
   - S3 scoped to workshop bucket prefixes
   - ELB lifecycle (Open WebUI load balancer)
   - ECR Public read (Neuron helm chart, base images)
   - STS (IRSA, eksctl)

Also add static/vscode_instance_role_policy.json as a standalone
reference document mirroring the inline policy, useful for Terraform
parity or manual policy application.
